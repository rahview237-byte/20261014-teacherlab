# 학급 경영 및 칭찬 관리 앱 제품 요구사항 정의서

최신 변경(2026-10-14): [학생 로그인·직접 적립 명세](docs/login-and-self-praise.md)를 우선 적용한다. 학생별 4자리 로그인, 교사 로그인, 매일 변경되는 칭찬 코드와 학생별 하루 2회 직접 적립, 30칸 가로 막대, 교사 일괄 칭찬을 반영한다. 아래 이전 버전의 시상·비밀편지는 현재 범위에서 제외한다.

버전 0.1 · 작성일 2026년 10월 12일 · 상태 제품 정책 검토용

2026년 10월 13일 반영: 학급 첫 화면에 우리 반 학급 규칙과 네 가지 문구를 표시한다. 네 번째 규칙은 배려하는 어린이다.

추가 확정: 개인칭찬은 학기당 네 영역 각각 30칸, 모둠칭찬은 정리·다했어요 각각 15칸이다. 학급온도계는 P0 핵심 기능이며 0~100도, 교사 전체 칭찬 1회당 +5도다. 5~100도 보상 내용 20칸은 빈칸으로 시작한다. 세부 모델·학기·취소 정책은 [칭찬판과 보상 설계](docs/stamp-and-rewards.md)를 따른다.

이 제품은 교사가 수업 중 학생의 좋은 행동을 빠르게 기록하고, 학생이 자신의 성장과 학급의 성취를 확인하며, 필요한 이야기를 교사에게 비공개로 전할 수 있도록 돕는다. 첫 출시에서는 **칭찬 기록 → 학생 확인 → 교사 검토를 거친 시상**을 핵심 흐름으로 완성한다. 모둠 활동과 비밀편지는 이 흐름과 함께 제공하되, 상담 내용은 공개 화면과 완전히 분리한다.

이 문서는 제품 책임자, 디자이너, 개발자, 테스트 담당자가 개발 범위와 완료 기준을 합의하기 위한 PRD다. 원문의 기능 방향을 유지하고, 구현에 필요한 정책과 예외 처리를 보완했다. 아래의 구체적 수치, 우선순위, 권한, 계산 방식은 별도 표시가 없어도 **검토를 위한 제안값**이며, 이미 확정된 사용자 결정으로 취급하지 않는다.

## 1 제품 방향과 개선 요약

### 1.1 원문에서 유지하는 요구

- 교사의 입력 부담을 줄이고 칭찬한 날짜를 도장으로 표시한다.
- 개인 칭찬은 자주적, 긍정적, 적극적, 배려의 네 영역으로 운영한다.
- 모둠장이 정리와 과제 완료를 점검한다.
- 교사가 시상 추천 결과를 검토한 뒤 학생에게 공개한다.
- 같은 회차의 중복 수상을 막고 최근 수상자를 후순위로 둔다.
- 학생의 비밀편지와 교사의 개인 지도 기록을 비공개로 관리한다.
- 발표 뽑기와 학급 온도계로 수업 및 공동 목표를 지원한다.

## 2 문제와 성공 기준

### 2.1 해결할 문제

교사는 수업 중 관찰한 행동을 별도 장부에 기록할 시간이 부족하다. 기록이 누락되거나 기억에 의존하면 시상 근거를 다시 정리해야 한다. 학생은 어떤 행동으로 언제 칭찬받았는지 확인하기 어렵고, 반복 수상으로 인정받을 기회가 일부 학생에게 집중될 수 있다. 공개 칭찬과 비공개 상담을 같은 화면에서 다루면 교실 화면 공유에 부담이 생긴다.

위 문제는 원문의 제품 의도를 정리한 가설이다. 실제 사용 빈도와 효과는 교사·학생 파일럿에서 확인한다.

### 2.2 제품 목표

1. 교사가 수업 흐름을 크게 끊지 않고 칭찬을 기록하고 실수를 바로 정정한다.
2. 학생이 칭찬의 영역과 날짜를 확인하고, 모둠 활동에 참여한다.
3. 교사가 설명 가능한 후보 추천을 바탕으로 시상을 확정한다.
4. 비밀편지를 작성한 학생과 담당 교사만 그 내용과 답글을 읽는다.

### 2.3 검증 지표

아래 목표는 측정 전의 제안값이다. 시범 운영 결과를 보고 조정한다.

| 지표 | 정의와 측정 방법 | 초기 목표 |
| --- | --- | --- |
| 칭찬 조작 시간 | 빠른 기록 모드에서 대상 학생을 찾은 뒤 기록 입력을 끝내기까지 사용성 테스트로 측정 | 중앙값 1초 이내 |
| 저장 응답 | 칭찬 입력부터 서버의 저장 확인까지 | 정상 네트워크에서 95%가 2초 이내 |
| 학생 화면 반영 | 저장 확인부터 접속 중인 학생 화면 갱신까지 | 정상 네트워크에서 95%가 3초 이내 |
| 시상 준비 시간 | 추천 버튼 선택부터 게시 완료까지 사용성 테스트로 측정 | 중앙값 3분 이내 |
| 칭찬 도달 범위 | 기간 내 1회 이상 칭찬받은 활성 학생 수 ÷ 기간 내 활성 학생 수 | 초기 2주 기준선 확인 후 교사가 검토 |
| 지속 사용 | 학급당 칭찬을 기록한 수업일 수 | 파일럿 종료 시 실제 수업일과 비교 |
| 데이터와 권한 정확성 | 중복 지급, 다른 학생 편지 조회, 승인 전 공개 테스트 | 출시 필수 시나리오 모두 통과 |

칭찬 수나 수상자 수를 늘리는 것 자체를 성공으로 정의하지 않는다. 도달 범위는 교사의 관찰을 돕는 지표로만 사용하고 학생 평가나 교사 순위에 사용하지 않는다.

## 3 사용자와 운영 가정

### 3.1 사용자

- **담임교사**는 학급을 만들고 학생과 모둠을 관리한다. 칭찬 기록, 정정, 시상 승인, 비밀편지 답변을 수행한다.
- **학생**은 칭찬판과 학급 공지를 확인하고 자신의 비밀편지를 작성한다.
- **모둠장**은 학생 권한에 더해 본인 모둠의 당일 점검 항목을 수정한다.
- **교실 공개 화면**은 로그인 역할이 아니라 교사가 명시적으로 여는 제한된 표시 모드다.

### 3.2 첫 출시의 운영 가정

- 초등학교 한 학급의 담임교사 1명을 우선 사용자로 가정한다. 대상 학년은 최종 확인이 필요하다.
- 교사는 PC·태블릿, 학생은 태블릿·휴대전화·공용 기기로 이용한다.
- 설치 없이 접속하는 반응형 웹 앱을 우선 제안한다. 앱스토어 배포는 첫 출시 범위에서 제외한다.
- 교사 계정은 여러 학급을 보유할 수 있지만, 각 학급의 관리 교사는 1명이다. 공동 담임과 교사 간 양도는 후속 범위다.
- 기본 카드 배치는 25명이며, 학급당 1~40명을 초기 지원 범위로 제안한다.
- 기준 시간대는 Asia/Seoul이다. 서비스 내부 시간 저장 형식과 무관하게 날짜 경계와 화면 표시는 이 기준을 따른다.

## 4 개발 범위와 우선순위

P0는 첫 출시의 필수 기능, P1은 첫 출시 검증 후 추가할 기능이다. 일정과 비용은 기술 검토 전이므로 이 문서에서 확정하지 않는다.

| P0 | 인증과 학급 설정 | 교사 로그인, 학생 접속, 명단, 학급 분리, 학급 보관 |
| P0 | 개인 칭찬 | 학기당 네 영역 각각 30칸, 빠른 기록, 날짜 도장, 취소 이력 |
| P0 | 학생 칭찬판과 공개 화면 | 같은 학급 칭찬판, 본인 상세, 공개 화면 분리 |

첫 출시에서는 벌점·감점, 학생 간 점수 거래, AI 상담·감정 판정, 자동 생활기록부 작성, 학교 행정 시스템 연동을 구현하지 않는다. 발표 뽑기는 후속 기능이며 학급온도계는 첫 출시의 핵심 기능이다.

## 5 핵심 사용 흐름

### 5.1 처음 사용하는 교사

1. 로그인하고 학급명과 학년도를 입력한다.
2. 학생 번호와 표시명을 직접 입력하거나 여러 줄로 붙여 넣는다.
3. 중복 번호와 비어 있는 이름을 확인한 뒤 명단을 저장한다.
4. 모둠을 만들고 학생 및 모둠장을 지정한다.
5. 학생 접속 수단을 발급하고 교사가 각 학생에게 배부한다.
6. 학생 화면과 공개 화면의 미리보기를 확인한 뒤 운영을 시작한다.

### 5.2 수업 중 칭찬

1. 교사가 빠른 기록 모드를 열고 칭찬 영역을 선택한다.
2. 학생 카드를 한 번 누른다.
3. 앱은 해당 카드에 저장 중 상태를 표시하고 서버에 기록한다.
4. 저장 확인 후 날짜 도장을 표시하고 실행 취소 버튼을 제공한다.
5. 접속 중인 학생 화면이 갱신된다. 다른 영역은 상단에서 바꾼다.

### 5.3 하교 전 모둠 점검

1. 모둠장이 본인 모둠 화면을 연다.
2. 주변 정리와 다했어요를 각각 체크한다.
3. 둘 다 완료되면 오늘 모둠 완료 메시지를 표시한다.
4. 교사는 미완료 현황을 확인하고 필요한 경우 정정한다.

### 5.4 비밀편지

1. 학생이 본인의 비밀편지 화면에서 내용을 작성한다.
2. 받는 사람이 담당 교사임을 확인하고 제출한다.
3. 교사는 비공개 편지함에서 내용을 읽고 읽었어요 버튼 또는 답글을 보낸다.
4. 학생은 자신의 편지에서 상태와 답글을 확인한다.

### 5.5 금요일 시상

1. 교사가 대상 주와 집계 마감을 확인하고 추천을 실행한다.
2. 앱은 부문별 후보, 선정 근거, 후순위 적용 여부를 보여준다.
3. 교사는 후보를 유지하거나 변경하고 공개될 문구를 미리 본다.
4. 게시 버튼을 누르면 확정된 결과만 칭찬 소식에 노출된다.

## 6 상세 기능 요구사항

### F01 인증과 학급 구성

**요구사항**

- 교사는 인증된 계정으로 접속한다. 계정 복구가 가능해야 한다.
- 학생은 교사가 발급한 개인 접속 코드와 개인 PIN 등으로 본인 신원을 확인한다. 학급 코드와 출석번호만으로 개인 편지를 열 수 없어야 한다. 정확한 인증 수단은 기술 설계에서 확정한다.
- 접속 코드는 재발급·폐기가 가능하고, 시도 횟수 제한과 실패 지연을 적용한다. PIN 원문을 저장하거나 교사에게 보여주지 않는다.
- 번호와 이름은 변경 가능한 속성으로 취급한다. 기록은 변경되지 않는 학생 식별자에 연결한다.
- 전출 학생은 비활성화한다. 기존 기록은 보존하되 칭찬·추첨·신규 추천 대상에서 제외하고 접속 권한을 해제한다.
- 학급 보관 시 학생 접속과 신규 기록을 막고, 교사는 보관 데이터를 조회·내보내기·삭제할 수 있다.

**수용 기준**

- 번호가 중복된 명단은 저장되지 않고 오류 행이 표시된다.
- 학생 이름이나 번호를 바꿔도 기존 칭찬과 편지가 같은 학생에게 유지된다.
- 다른 학급 또는 다른 학생 식별자로 직접 요청해도 권한 없는 데이터가 반환되지 않는다.

### F02 개인 칭찬 기록

**기본 영역**

| 영역 | 교사가 선택할 때 보여줄 행동 예시 |
| --- | --- |
| 자주적 | 스스로 준비하기, 자기 주변 정리하기 |
| 긍정적 | 친구 돕기, 격려하기 |
| 적극적 | 발표하기, 질문하기, 활동에 참여하기 |
| 배려 | 차례 지키기, 상대를 존중하기 |

위 행동 예시는 영역의 중복과 기타 항목의 모호함을 줄이기 위한 제안이다. 첫 출시에서는 네 영역을 고정하고, 영역 이름과 예시는 교사가 학생에게 설명할 수 있어야 한다.

**요구사항**

- 기본 입력은 학생 선택 후 영역 선택이다. 빠른 기록 모드에서는 선택된 영역을 유지하고 학생 카드 한 번 선택으로 1건을 기록한다.
- 빠른 기록 모드는 켜짐 상태와 현재 영역을 항상 크게 표시한다. 학급 전환 시 모드를 종료한다.
- 한 건은 한 학생·학기·영역에 속한다. 자주적·긍정적·적극적·배려 각각 독립된 30칸 판을 제공하고 유효 칭찬 1건을 도장 1개로 계산한다. 30개 도달 후 해당 영역의 추가 지급은 차단한다.
- 같은 날 같은 영역도 상한 안에서는 여러 번 받을 수 있다. 개별 칸에는 날짜를 표시하고 영역별 진행 수를 함께 보여준다. 취소하면 빈칸이 생기며 새 학기에만 새 빈 판을 시작한다. 이전 학기 판은 보존한다.
- 기본 행동 날짜는 오늘이다. 교사는 별도 정정 화면에서 지난 날짜 기록을 추가할 수 있으며 실제 입력 시각과 정정 이유를 남긴다. 미래 날짜는 허용하지 않는다.
- 빠른 연속 입력과 네트워크 재시도로 같은 요청이 두 번 저장되지 않아야 한다. 저장 중인 카드의 반복 입력은 차단하고 요청 식별자로 중복 저장을 방지한다.
- 저장 확인 후 5초간 실행 취소를 제공한다. 이후에도 이력에서 사유와 함께 취소 가능하다. 기존 행을 조용히 덮어쓰지 않고 취소 상태와 수행자를 기록한다.
- 오프라인에서는 저장 완료로 표시하지 않는다. 현재 화면에서 미저장 항목과 재시도를 제공한다. 브라우저 종료 이후의 오프라인 복구는 첫 출시 범위가 아니다.

**수용 기준**

- 자주적 영역을 선택하고 학생 카드를 한 번 누르면 해당 학생에게 오늘 날짜의 도장이 한 개 저장된다.
- 같은 요청을 재전송해도 도장은 한 개만 생성된다.
- 취소된 기록은 칭찬판과 시상 집계에서 제외되며 교사 이력에는 남는다.
- 저장 실패 시 도장 확정 표시가 없고 다시 시도할 수 있다.
- 29개에서 30개는 성공, 31번째 지급은 거부한다. 마지막 칸의 동시 요청에서도 30개를 넘지 않으며 다른 영역의 개수에 영향을 주지 않는다.

### F03 학생 칭찬판과 교실 공개 화면

**요구사항**

- 학급에 들어온 뒤 첫 화면은 **우리 반 학급 규칙**이다. 교사와 학생 모두 아래 네 문구를 이 순서로 가장 먼저 확인한다.
  1. 자주적인 어린이
  2. 긍정적인 어린이
  3. 적극적인 어린이
  4. 배려하는 어린이
- 첫 화면의 중심에는 네 규칙을 배치한다. 그 아래에 학생은 내 칭찬판·모둠 칭찬판·학급온도계·칭찬 소식·비밀편지, 교사는 칭찬 기록·모둠칭찬·학급온도계·주간 시상·비밀 편지함으로 이동할 수 있는 메뉴를 제공한다.
- 다른 메뉴에서 학급 첫 화면으로 돌아올 수 있어야 한다. 매번 확인 버튼을 누르거나 동의해야 다음 화면으로 넘어가는 절차는 두지 않는다.
- 학급 규칙 네 문구는 첫 화면의 교육 목표다. 자주적·긍정적·적극적·배려의 개인 칭찬 영역과 의미를 맞추되, 안내 문구와 칭찬 데이터의 코드는 별도로 관리한다.
- 내 칭찬판은 네 영역과 날짜 도장을 보여주며 월별로 조회한다. 표시 예시는 10/12 도장 2개이다. 연도를 넘는 조회에서는 연도도 표시한다.
- 같은 학급 친구의 공개 칭찬판을 볼 수 있되 전체 순위표는 제공하지 않는다.
- 교실 공개 화면은 별도 진입점으로 제공한다. 교사용 관리 패널을 단순히 숨기는 방식에 의존하지 않는다.
- 공개 화면에는 확정된 칭찬과 모둠 완료, 게시된 수상 결과만 제공한다. 편지 내용, 편지 도착 알림, 지도 노트, 미확정 후보는 데이터 요청 단계부터 제외한다.
- 교실 공개 모드에서 교사 관리 화면으로 돌아갈 때 교사 재인증을 요구한다.

**수용 기준**

- 학생 A는 학생 B의 공개 칭찬판은 보지만 B의 편지와 개인 합계 분석은 볼 수 없다.
- 공개 화면 실행 중 새 편지가 도착해도 학생 이름이나 알림이 나타나지 않는다.
- 학급에 처음 진입하면 제목과 네 규칙이 정확한 문구·순서로 표시되고, 각 역할의 메뉴로 이동한 뒤 첫 화면으로 돌아올 수 있다.

### F04 모둠 구성과 칭찬 스탬프 판

**요구사항**

- 교사는 모둠을 만들고 소속 학생과 모둠장 1명을 지정한다. 학생은 한 시점에 최대 한 모둠에 속한다.
- 주변 정리와 다했어요를 매일 각각 참 또는 거짓으로 저장한다. 두 항목이 모두 참일 때 완료 상태다.
- 모둠장만 자신의 모둠의 오늘 항목을 변경한다. 교사는 모든 모둠의 오늘 및 과거 기록을 사유와 함께 정정할 수 있다.
- 자정 이후에는 새 날짜 기록을 표시한다. 전날 미완료 상태를 오늘 완료로 이어받지 않는다.
- 모둠장 변경은 즉시 쓰기 권한에 반영한다. 과거 기록은 당시 모둠과 작성자에 연결해 유지한다.
- 모둠 점검 완료는 개인 칭찬이나 주간 개인 시상 점수로 자동 변환하지 않는다.
- 핵심 칭찬판은 모둠별 정리 15칸과 다했어요 15칸이다. 각각 학기별 누적하고 날짜가 바뀌어도 유지한다. 교사 확인 후 영역별 도장을 지급하는 안으로 설계하며 모둠장의 체크는 자동 도장 지급과 분리한다.
- 영역별 15개 도달 후 추가 지급을 차단하고, 취소 시 빈칸을 복구한다. 모둠원 변경 시 도장을 개인에게 이월하지 않는다. 새 학기에 새 판을 만들고 기존 판은 보존한다.

**수용 기준**

- 일반 학생이나 다른 모둠장은 체크 상태를 변경할 수 없다.
- 같은 체크 요청을 반복해도 점검 행이나 보상이 중복 생성되지 않는다.
- 두 화면에서 동시에 수정하면 최신 상태를 다시 불러오도록 안내해 조용한 덮어쓰기를 막는다.
- 정리와 다했어요는 각각 15칸이며 16번째 지급과 마지막 칸의 동시 초과 지급을 거부한다. 일별 체크 초기화가 누적 도장을 지우지 않는다.

### F05 시상 추천과 게시

**화면 및 주기**

- 교사 메뉴는 주간 시상, 학생 메뉴는 칭찬 소식으로 통일한다.
- 기본 시상은 주 1회이며 네 칭찬 영역별 1명, 최대 4명이다.
- 학생은 이번 주 수상 결과와 월별 과거 결과를 확인한다. 별도의 월간 상 계산은 첫 출시에서 제공하지 않는다.
- 같은 학급·같은 주에는 활성 시상 회차를 하나만 허용한다. 정정은 기존 회차의 새 버전으로 처리한다.

**집계 규칙**

1. 기본 집계 기간은 선택한 주의 월요일 00시부터 금요일 23시 59분 59초까지다. 금요일 도중 추천하면 실제 집계 마감은 추천 실행 시각이다. 토·일 기록은 보관하되 기본 주간 시상 집계에는 넣지 않는다.
2. 대상 주, 시작·종료 시각과 실제 집계 마감을 추천 화면에 표시한다. 교사가 시상 기간을 임의로 겹치게 만드는 기능은 첫 출시에서 제외한다.
3. 행동 날짜가 기간에 포함되고 집계 시점까지 저장된 유효한 칭찬만 집계한다. 취소된 기록은 제외한다.
4. 각 영역의 점수는 해당 영역의 유효한 칭찬 건수다. 현재 활성 상태이고 해당 영역 점수가 1 이상인 학생만 그 영역의 후보가 된다.
5. 최근 수상 여부는 추천 기준일 0시에서 14일 전 0시까지의 구간에 게시된 유효 수상 이력으로 판단한다. 구간의 시작은 포함하고 종료는 포함하지 않는다. 당일 다른 회차 수상은 후보 화면에 별도로 경고한다.

**추천 순서**

- 먼저 최근 14일 수상이 없는 학생을 우선 후보군, 있는 학생을 후순위 후보군으로 나눈다.
- 각 영역에서 아직 이번 회차 수상자로 배정되지 않은 학생 중 우선 후보군을 먼저 사용한다. 없으면 후순위 후보군으로 넘어가고 그 사실을 표시한다.
- 동일 후보군에서는 해당 영역 칭찬 수가 많은 순, 해당 학년도 유효 수상 횟수가 적은 순, 마지막 수상이 오래된 순으로 정렬한다. 수상 이력이 없는 학생은 마지막 기준에서 우선한다.
- 모든 조건이 같으면 회차별 고정 난수로 동점을 처리한다. 같은 자료로 다시 열거나 새로고침해도 결과가 바뀌지 않는다. 동점 처리에 사용한 값은 이력에 남긴다.
- 한 학생은 한 회차에서 한 부문에만 배정한다. 한 부문에서 선택되면 다음 부문의 후보에서 제외한다.
- 영역 처리 순서는 기본적으로 자주적 → 긍정적 → 적극적 → 배려이며, 시상 주의 ISO 주차를 4로 나눈 나머지만큼 시작점을 순환한다. 예를 들어 나머지가 1이면 긍정적부터 시작한다. 실제 순서를 후보 화면과 회차에 저장한다.
- 해당 영역에 배정 가능한 양수 점수 후보가 없으면 수상자 없음으로 남긴다. 네 명을 채우기 위해 임의의 학생을 자동 추가하지 않는다.

이 방식은 점수 최댓값만을 뽑는 방식보다 최근 수상 집중을 줄이는 데 우선순위를 둔다. 부문 순서에 따라 결과가 달라질 수 있으므로 처리 순서와 이유를 표시한다. 알고리즘이 교육적 공정성을 보장한다고 표현하지 않는다.

**교사 검토와 게시**

- 후보별로 집계 건수, 최근 수상 여부, 학년도 수상 횟수, 추천 이유를 보여준다. 이 정보는 교사만 본다.
- 교사는 다른 활성 학생으로 교체할 수 있으며 변경 이유를 입력한다. 점수 0인 학생을 관찰 근거로 선정하는 예외도 가능하되 명시적으로 경고한다. 한 회차 1인 1상 제약은 수동 변경에도 유지한다.
- 추천 후 칭찬, 취소, 학생 활성 상태 또는 관련 수상 이력이 바뀌면 초안을 갱신 필요 상태로 만든다. 교사는 재계산하고 수동 변경 사항을 다시 확인한 뒤 게시한다.
- 게시 전 대상 학생, 영역, 공개 문구를 미리 보여준다. 게시와 승인 이력 저장은 함께 성공하거나 함께 실패해야 한다.
- 게시된 결과는 이후 점수 정정만으로 자동 교체하지 않는다. 영향이 있음을 교사에게 표시하고 교사가 정정 또는 철회한다.
- 철회한 수상은 후속 추천의 유효 수상 이력에서 제외한다. 학생 화면에는 혼란을 줄이기 위해 정정된 결과 또는 공지 철회 상태를 표시한다.

**수용 기준**

- 같은 회차의 네 부문 결과에 같은 학생이 두 번 들어가지 않는다.
- 비수상 후보 A가 3개, 최근 수상 후보 B가 6개를 받았다면 A를 먼저 추천하고 후순위 기준을 설명한다.
- 양수 점수 후보가 모두 최근 수상자이면 그중 기준에 맞는 학생을 추천하고 후순위 후보 사용을 표시한다.
- 후보가 부족하면 일부 부문은 비어 있고, 교사는 빈 부문을 확인한 후 게시할 수 있다.
- 게시 전에는 학생이 후보를 볼 수 없고, 중복 게시 요청을 보내도 공지가 중복 생성되지 않는다.

### F06 비밀편지와 교사 지도 노트

**요구사항**

- 메뉴명은 비밀편지로 단순화한다. 원문의 이달의 표현은 월별 조회 구분으로 사용하고 발송을 월 1회로 제한하지 않는다.
- 학생은 1~2,000자의 글을 작성한다. 첫 출시에서는 텍스트만 지원하고 파일·사진 첨부는 제외한다.
- 제출 전 글은 현재 화면에서 수정할 수 있다. 공용 기기 보호를 위해 본문을 브라우저 영구 저장소에 자동 보관하지 않는다. 화면을 나갈 때 작성 내용이 사라짐을 안내한다.
- 제출 후에는 원문을 수정하지 않는다. 학생은 같은 대화에서 추가 글을 보낼 수 있다.
- 상태는 보냈어요 → 선생님이 확인했어요 → 답장이 왔어요로 구분한다. 단순히 편지 목록을 열었다고 학생에게 읽음 상태를 보내지 않는다.
- 교사가 읽었어요를 누르거나 답글을 보낼 때 확인 상태가 바뀐다. 답글을 보냈다면 확인과 답장 상태를 함께 기록한다.
- 교사는 비밀편지를 열기 전에 재인증한다. 민감 화면은 5분 비활동 시 잠금으로 전환하는 안을 제안한다. 생체인증은 지원 기기의 선택적 인증 수단이며 필수 전제가 아니다.
- 지도 노트는 편지와 연결된 별도 교사 전용 기록으로 작성한다. 이관 버튼이 편지를 학생 화면에서 삭제하거나 노트를 학생에게 공개하는 의미가 되어서는 안 된다.
- 앱은 실시간 상담 서비스가 아님을 작성 화면에 짧게 안내하고, 급한 도움이 필요하면 가까운 선생님에게 직접 알리도록 안내한다. 자동 상담이나 위험도 판정은 제공하지 않는다.

**수용 기준**

- 학생은 본인의 편지와 교사 답글만 볼 수 있다.
- 모둠장 권한을 얻어도 다른 학생의 편지를 볼 수 없다.
- 교사가 읽었어요를 누르면 해당 학생에게만 상태가 반영된다.
- 지도 노트를 생성해도 학생에게는 원래 편지와 학생용 답글만 보인다.
- 로그아웃 또는 접속 권한 해제 뒤 뒤로 가기를 눌러도 민감 내용을 다시 불러오지 못한다.

### F07 발표 뽑기

P1 기능이다. 교사는 현재 활성 학생 중 당일 참여 대상을 고르고 1명 또는 N명을 추첨한다. 한 번의 추첨에서 중복은 허용하지 않는다. N이 참여 인원보다 크면 실행할 수 없다.

같은 수업의 이미 뽑힌 학생을 제외하는 옵션과 수업 추첨 초기화 기능을 제공한다. 결석 여부는 이 기능에서의 제외 선택으로만 처리하며 별도의 출결 관리 제품으로 확장하지 않는다. 각 추첨은 적격 학생에게 같은 확률을 적용하고 칭찬 점수나 수상 이력으로 확률을 바꾸지 않는다.

추첨 결과에는 적극적 칭찬 버튼을 제공하지만, 뽑혔다는 이유만으로 도장을 자동 지급하지 않는다. 애니메이션 생략 옵션을 제공한다.

수용 기준은 N명 모두 적격하고 서로 다르며, 칭찬 버튼을 누르기 전에는 칭찬 데이터가 생성되지 않는 것이다.

### F08 학급 온도계

P0 핵심 기능이다. 반 전체가 잘했을 때 교사가 전체 칭찬을 지급한다. 온도는 0도에서 시작해 1회당 정확히 5도씩 올라가고 100도가 상한이다. 목표 온도와 증가량은 고정한다.

교사는 증가와 오입력 취소를 할 수 있다. 온도는 0도 이상 목표 온도 이하로 제한한다. 목표 도달 시 축하 상태를 한 번 표시하고, 교사가 새 목표 주기를 시작하기 전까지 유지한다. 초기화는 이전 주기를 삭제하지 않고 새 주기를 만든다.

개인 칭찬 수나 모둠 체크를 온도로 자동 환산하지 않는다. 5·10·15·…·100도 각각에 보상 입력란을 하나씩 제공하며, 20개 내용은 모두 빈칸으로 시작한다. 학생과 상의한 내용을 교사가 나중에 입력한다. 내용이 비어 있어도 온도를 올릴 수 있으며 보상을 자동 지급하지 않는다. 100도에서 증가를 막고 오입력 취소는 원래 칭찬 한 건당 5도를 되돌린다.

수용 기준: 20회 지급 후 100도, 21번째 및 95도에서의 동시 초과 지급 거부, 중복 요청·취소 방지, 초기 보상 내용 20개 모두 빈칸, 교사만 보상 편집 가능. 새 주기는 자동 시작하지 않으며 이전 주기와 보상표를 보존한다.

## 9 품질과 정보 보호 요구사항

### 9.1 성능과 사용성

- 초기 검증 조건은 학급당 40명, 교사 1명과 학생 40명 동시 접속이다. 학교 규모의 동시 학급 수는 배포 계획에서 별도 확정한다.
- 학생 카드와 주요 버튼은 터치로 쉽게 선택할 수 있어야 한다. 최소 44 CSS px의 조작 영역을 제안한다.
- 키보드만으로 칭찬 입력과 시상 검토를 완료할 수 있어야 한다.
- 저장 성공·실패와 영역 구분을 색상이나 이모지만으로 전달하지 않는다. 텍스트 설명을 함께 제공한다.
- 칭찬 기록 중 페이지를 새로고침해도 서버에 저장된 상태를 다시 확인할 수 있어야 한다.
- 서버 응답 전 낙관적 표시를 사용하더라도 저장 중과 확정 상태를 구분한다.

### 9.2 접근과 저장

- 권한은 화면 숨김과 별개로 서버에서 모든 요청마다 검증한다. 학생, 학급, 역할 변경과 세션 폐기를 반영한다.
- 전송 구간을 암호화하고 저장된 민감 정보의 암호화 및 운영자 접근 통제를 적용한다.
- 비밀편지와 지도 노트 본문을 분석 이벤트, 오류 로그, 공개 알림에 포함하지 않는다.
- 공개 화면은 허용된 공개 데이터만 받는다. 교사의 편지 데이터를 브라우저에 미리 가져와 숨겨 두지 않는다.
- 공용 기기에서 계정 전환 시 이전 학생 데이터와 임시 입력을 지운다. 민감 응답의 브라우저 캐시 저장을 제한한다.
- 서비스 운영자가 교육 기록을 조회해야 하는 상황은 별도의 통제·기록 절차로 설계하며 일상적인 열람 기능을 제공하지 않는다.

### 9.3 보관과 삭제

- 학년도 종료 시 학급을 보관할 수 있다. 새 학년 명단을 만들 때 기존 칭찬·수상·편지를 자동 이월하지 않는다.
- 기록 내보내기는 담당 교사만 가능하고, 비밀편지와 지도 노트는 공개 칭찬 자료와 분리해 선택적으로 내보낸다.
- 개별 기록 취소, 학급 보관, 개인정보 삭제를 서로 다른 동작으로 구분한다.
- 실제 삭제에는 운영 저장소뿐 아니라 백업의 만료·복구 시 재삭제 절차도 포함한다. 보관 기간과 백업 만료 기간은 출시 전 확정한다.
- 필수 수집 항목은 학급, 학생 표시명·번호, 접속 정보와 서비스 사용에 필요한 기록으로 제한한다. 주민등록번호, 주소, 개인 전화번호는 수집하지 않는다.

학생 데이터 처리 주체, 학교의 운영 절차, 필요한 동의·고지, 보관 기간은 실제 배포 환경에 맞춰 별도 검토한다. 이 PRD는 법적 적합성을 판정하거나 특정 보관 기간이 법정 의무라고 규정하지 않는다.

## 10 검증 계획과 출시 기준

### 10.1 필수 검증 시나리오

| 시나리오 | 기대 결과 |
| --- | --- |
| 동일 칭찬 요청을 연속 재전송 | 한 건만 저장 |
| 저장 중 네트워크가 끊겼다가 재시도 | 저장 여부를 확인하며 중복 지급 없이 복구 |
| 같은 날 같은 영역에 서로 다른 칭찬 두 건 | 도장 두 개로 집계 |
| 칭찬 취소 또는 지난 날짜 추가 | 학생 화면과 해당 기간 집계에 반영 |
| 월요일 0시와 금요일 집계 마감 경계 | 서울 시간대 기준으로 정확히 포함 또는 제외 |
| 최근 14일 구간 경계의 수상 | 정의한 시작 포함·종료 제외 규칙 적용 |
| 한 학생이 모든 영역에서 높은 점수 | 최대 한 부문만 수상 |
| 완전 동점 및 반복 추천 | 데이터가 같으면 같은 결과 |
| 후보 0명 또는 4명 미만 | 미선정 부문 표시, 임의 후보 생성 없음 |
| 초안 생성 후 칭찬 또는 명단 변경 | 갱신 필요 표시, 재검토 전 게시 차단 |
| 게시된 수상에 영향을 주는 칭찬 취소 | 자동 수상자 교체 없이 교사 정정 안내 |
| 다른 학생이나 다른 학급의 편지 직접 요청 | 접근 거부 및 본문 미반환 |
| 공개 모드에서 편지 도착 | 공개 화면과 응답에 민감 정보 없음 |
| 모둠장 교체 직후 이전 모둠장이 수정 | 접근 거부 |
| 전출 처리 후 기존 세션 사용 | 추가 데이터 조회와 기록 불가 |
| 공용 기기에서 로그아웃 후 뒤로 가기 | 이전 학생의 민감 데이터 노출 없음 |
| 학급 삭제와 백업 복구 검증 | 확정된 보관·삭제 정책대로 처리 |

### 10.2 파일럿

먼저 가상 학생으로 핵심 흐름과 권한을 검증한다. 이후 실제 운영 조건이 준비된 1~2개 학급에서 2주간 파일럿을 진행하는 안을 제안한다. 교사의 기록 시간과 시상 준비 시간, 잘못 입력한 기록의 정정 경험, 학생의 날짜 도장 이해도, 모둠장의 체크 수행 여부를 확인한다.

반복적으로 칭찬을 받지 못하는 학생이 생기는지와 시상 추천을 교사가 얼마나 자주 수정하는지도 살펴본다. 편지 본문은 제품 분석 자료로 수집하지 않는다. 추천 수정 사유는 내용 자체를 외부 분석에 보내지 않고 수정 빈도 등 최소한의 집계로 확인한다.

### 10.3 출시 통과 조건

- P0의 주요 흐름과 필수 검증 시나리오를 통과한다.
- 권한 우회, 편지 노출, 중복 칭찬, 승인 전 시상 노출 문제가 남아 있지 않다.
- 명단 변경, 수상 정정, 학급 보관·삭제의 운영 경로가 제공된다.
- 실제 지원 기기와 네트워크에서 핵심 성능 목표를 검증한다.
- 아래의 출시 전 결정 사항을 확정하고 제품 문구와 테스트에 반영한다.

## 11 개발 전 결정할 사항

각 항목의 현재 안으로 화면 설계와 견적 검토를 진행할 수 있다. 다만 출시 전에는 제품 책임자가 정책을 확정해야 한다.

| 결정할 사항 | 현재 제안 | 결정이 필요한 이유 |
| --- | --- | --- |
| 대상 학년과 학생 기기 | 초등학교, 학생이 웹 접속 가능한 환경 | 글쓰기 수준과 접속 방식에 영향 |
| 개인 칭찬 공개 범위 | 같은 학급의 영역·날짜 도장 공개, 순위 제외 | 원문의 공개 칭찬 취지를 구체화 |
| 학생 인증 | 교사 발급 개인 접속 수단과 PIN 조합 | 공용 기기에서 본인 확인 필요 |
| 시상 주기 | 주간 시상, 월별 기록 모아보기 | 주간과 월간 시상 혼용 해소 |
| 최근 수상자 후순위 강도 | 점수보다 최근 14일 미수상을 우선 | 높은 점수 학생과 기회 분산의 균형 |
| 주간 집계 대상일 | 월요일부터 금요일, 실행 시각까지 | 주말과 금요일 늦은 기록 처리 |
| 모둠장의 자율 체크 | 즉시 반영, 교사가 필요 시 정정 | 교사 승인 부담과 자기관리의 균형 |
| 학생 데이터 운영 | 배포 주체와 학교 운영 절차에 맞게 확정 | 고지·보관·삭제·문의 경로 설계 |
| 후속 수업 도구 | 발표 뽑기는 후속, 온도계는 첫 출시 포함으로 확정 | 초기 일정과 범위 반영 |

## 12 권장 구현 순서

1. **정책과 화면 검증** — 11장의 핵심 결정, 교사 칭찬 입력과 학생 공개 범위, 시상 예시를 확정한다.
2. **기본 운영 구현** — 인증, 학급과 명단, 개인 칭찬, 정정 이력, 학생 칭찬판을 완성한다.
3. **시상 구현** — 집계, 추천 이유, 교사 승인, 공개 공지, 정정 흐름을 완성한다.
4. **모둠과 비밀편지 구현** — 역할별 권한, 재인증, 교실 공개 화면 분리까지 검증한다.
5. **운영 검증과 파일럿** — 데이터 삭제·내보내기, 실패 복구, 주요 기기 검증을 마친 뒤 시범 운영한다.
6. **수업 도구 확장** — 파일럿 결과에 따라 발표 뽑기를 추가한다. 학급온도계는 개인·모둠 칭찬과 함께 먼저 구현한다.

각 단계는 기능 구현과 해당 검증까지를 포함한다. 일정은 이 순서에 따른 작업량과 배포 환경을 확인한 뒤 산정한다.
