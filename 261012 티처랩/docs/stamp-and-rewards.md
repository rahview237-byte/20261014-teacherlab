# 학기별 칭찬판과 학급온도계 상세 설계

최신 변경(2026-10-14): [로그인·직접 적립 명세](./login-and-self-praise.md)에 따라 개인 판은 원형 스탬프 대신 30칸 가로 막대로 표시한다. 학생은 오늘의 코드로 네 영역 합산 하루 2회 직접 적립할 수 있고 교사 일괄 칭찬은 별도다. 기존 교사만 기록한다는 조건은 이 예외를 포함하도록 변경한다.

2026년 10월 13일 사용자 확정 요구 반영

앱의 핵심 기능은 개인 네 영역의 스탬프 판과 모둠 두 영역의 스탬프 판이다. 학급 전체를 칭찬하는 학급온도계도 첫 출시 필수 기능으로 포함한다. 이 문서는 기존 PRD의 무제한 기록 표현과 온도계 후속 개발 제안을 대체한다.

## 1 확정된 구성

| 프로그램 | 대상 | 영역 | 한도와 단위 |
| --- | --- | --- | --- |
| 개인칭찬 | 학생 개인 | 자주적·긍정적·적극적·배려 | 한 학기당 각 30칸, 합계 최대 120개 |
| 모둠칭찬 | 모둠 | 정리·다했어요 | 한 학기당 각 15칸, 합계 최대 30개 |
| 학급온도계 | 반 전체 | 학급 전체 칭찬 | 0도 시작, 교사의 칭찬 1회마다 5도 상승, 최대 100도 |
| 온도별 보상 | 반 전체 | 5·10·15·…·100도 | 20개 보상 입력란, 초기 내용 모두 빈칸 |

보상 내용은 학생들과 상의해서 정한다. 기본 예시 보상이나 임의의 상품·활동은 넣지 않는다. 개인·모둠 판의 완성에도 임의의 보상을 붙이지 않는다.

## 2 개인 스탬프 판

- 학년·학기를 표시하고 네 영역을 각각 독립된 30칸 판으로 제공한다. 한 영역을 채워도 다른 영역의 남은 칸에 영향을 주지 않는다.
- 빈칸과 받은 도장을 모두 보여주며 `12 / 30`과 같은 진행 수를 표시한다. 받은 도장에는 행동 날짜를 표시하고 상세에서 해당 기록을 확인한다.
- 교사가 영역을 선택하고 칭찬하면 빈칸 하나가 채워진다. 스탬프 칸 자체를 학생이 클릭해 지급할 수 없다.
- 유효 기록 30개가 되면 완료 상태로 바꾸고 추가 지급을 차단한다. 31번째 기록이나 숨은 초과 점수를 만들지 않는다. 주간 시상에도 실제 저장된 유효 칭찬만 사용한다.
- 같은 날 서로 다른 칭찬은 한도 내에서 여러 번 가능하다. 동일 요청의 재시도는 한 번만 반영한다.
- 오입력 취소는 해당 기록을 취소하고 유효 개수를 줄인다. 화면의 도장은 유효 기록 순서로 재배치하되, 기록 ID와 날짜·취소 이력을 유지한다. 빈칸이 생기면 다시 지급할 수 있다.
- 30개를 채웠다고 같은 학기 안에서 자동으로 새 판을 만들지 않는다.

## 3 모둠 스탬프 판

- 모둠별로 정리 15칸과 다했어요 15칸을 별도로 표시한다. 개인에게 분배하거나 개인 점수에 합산하지 않는다.
- 교사 지급 방식은 구현 제안이다. 기존 모둠장의 당일 체크는 자기 점검으로 유지하고, **교사가 확인 후 해당 영역에 칭찬 도장을 지급**한다. 체크만으로 자동 지급하지 않아 학생의 체크 반복으로 도장이 늘어나지 않게 한다.
- 두 체크를 모두 완료해야만 도장을 줄 수 있는 것은 아니다. 정리와 다했어요를 각각 칭찬할 수 있다.
- 날짜가 바뀌면 당일 체크는 새로 시작하지만 누적 스탬프는 유지한다. 15개 상한은 일별이 아니라 학기별이다.
- 같은 지급 요청 재시도는 한 건, 서로 다른 정당한 지급은 상한 내에서 별도 기록으로 처리한다. 일일 지급 횟수 제한은 추가하지 않는다.
- 모둠원이 바뀌어도 판은 해당 모둠에 남고 개인에게 옮겨가지 않는다. 모둠 이름 변경은 기록을 유지한다. 새 모둠 ID를 만들면 새 모둠 판을 사용하고 이전 모둠은 보관한다.
- 완성·취소·추가 지급 차단 규칙은 개인 판과 같으며 상한만 15다.

## 4 학기 관리

학급은 1학기·2학기를 구분하는 Semester를 가진다. 실제 시작일과 종료일은 학교 일정에 맞춰 교사가 설정하며 날짜를 임의로 고정하지 않는다. 학급 내 학기 기간은 겹치지 않게 한다.

판의 고유 키는 개인의 경우 `학급 + 학기 + 학생 + 영역`, 모둠은 `학급 + 학기 + 모둠 + 영역`이다. 새 학기는 새로운 빈 판으로 시작하고 이전 학기 기록을 삭제하거나 자동 이월하지 않는다. 영역을 바꾸거나 화면을 새로고침해도 누적 개수는 유지된다.

신규 기록은 선택한 활성 학기에만 지급한다. 행동 날짜도 그 학기 안에 있어야 한다. 이전 학기 기록은 조회와 사유 있는 오입력 취소를 지원하되 지난 학기에 새 칭찬을 추가하는 기능은 기본 제공하지 않는 안으로 제안한다. 이 규칙은 현재 PRD의 과거 날짜 입력을 활성 학기 범위로 구체화한다.

## 5 온도계와 보상

- 교사가 반 전체의 좋은 행동을 보고 `우리 반 칭찬 +5도`를 누른다. 학생·모둠장은 조회만 한다.
- 온도는 0, 5, 10, …, 100만 허용한다. 증가량·목표값을 임의로 편집하는 설정은 제공하지 않는다.
- 개인·모둠 스탬프 지급 또는 모둠 체크 완료를 온도로 자동 환산하지 않는다.
- 온도가 100도이면 완료 상태와 함께 증가 버튼을 비활성화한다. 105도나 자동 초기화가 발생하면 안 된다.
- 교사는 잘못 지급한 학급 칭찬을 취소할 수 있다. 취소 이력과 사유를 남기고 한 건당 5도를 되돌린다. 같은 원본을 두 번 취소하지 않는다.
- 온도계의 주기는 학기와 별개로 관리하는 안을 제안한다. 학기가 바뀌었다고 자동 초기화하지 않고, 교사가 새 주기를 시작할 때만 0도로 시작한다. 이전 주기의 온도와 보상표는 보관한다.
- 새 주기의 보상표도 20칸 모두 빈칸으로 만든다. 이전 보상 문구를 자동 복사하지 않는다.

### 보상 입력란

각 온도에 `rewardText`를 따로 저장한다. 학생들과 정한 내용을 교사가 입력·수정하며 학생에게는 조회만 허용한다. 보상표 화면에서 비어 있는 입력란의 실제 값은 빈 문자열이다. 빈 내용을 임의의 문구로 저장하지 않는다.

## 6 추가 모델과 일관성

| 모델 | 소유 모듈 | 주요 필드 |
| --- | --- | --- |
| Semester | classroom | id, classroomId, label, startsOn, endsOn, status |
| PersonalStampBoard | praise | id, classroomId, semesterId, studentId, category, limit=30, version |
| PraiseRecord | praise | boardId, occurredOn, recordedAt, requestId, status, cancellation |
| TeamStampBoard | teams | id, classroomId, semesterId, teamId, category=CLEANUP 또는 TASK_DONE, limit=15, version |
| TeamPraiseRecord | teams | boardId, occurredOn, recordedBy, requestId, status, cancellation |
| GoalCycle | class-goals | classroomId, currentValue, target=100, step=5, status, version |
| RewardMilestone | class-goals | cycleId, temperature, rewardText="", version |

새 도메인을 만들지 않고 각 도메인의 기록·조회 계약을 확장한다. 화면상의 모든 빈칸을 DB 행으로 만들 필요는 없다. 판과 유효 기록으로 빈칸을 계산한다.

스탬프 상한 검증과 기록 삽입은 **같은 판 잠금을 사용하는 DB 트랜잭션**에서 처리한다. 마지막 한 칸을 두 요청이 동시에 채우려 하면 한 요청만 성공해야 한다. 취소와 지급도 동일 잠금 규칙을 사용한다. 시상에 영향을 주는 개인 칭찬은 학급 잠금 → 판 잠금 순서로 통일하고 집계 자료 버전을 같은 트랜잭션에서 변경한다.

온도 변경·상쇄·새 주기 생성은 해당 학급의 목표 주기 잠금 아래 검증한다. 95도에서 서로 다른 두 증가 요청이 동시에 들어와도 100도를 넘지 않는다. 동일 요청 키 재전송은 기존 결과를 반환한다. 보상 내용 편집도 version 충돌을 감지하며 빈칸 상태를 허용한다.

## 7 추가 검수 기준

- 개인 각 영역이 정확히 30칸, 모둠 각 영역이 정확히 15칸으로 표시된다.
- 개인 29→30 성공·31번째 거부, 모둠 14→15 성공·16번째 거부. 마지막 칸 동시 지급에서도 초과하지 않는다.
- 같은 요청 재시도, 취소와 재지급, 영역·학생·모둠 간 격리가 정확하다.
- 새 학기는 0개이며 과거 학기는 보존된다. 자정에 누적 스탬프가 지워지지 않는다.
- 모둠장 체크만으로 도장이 지급되지 않고 일반 학생은 지급·취소·온도 변경을 할 수 없다.
- 온도는 0부터 시작해 20회 칭찬으로 100도, 21번째 요청은 거부한다. 95도 동시 증가·0도 취소·중복 취소도 검증한다.
- 5도부터 100도까지 5도 간격의 보상 입력란 20개가 정확히 존재하고 초기 내용이 모두 빈칸이다.
- 교사 보상 편집, 학생 조회, 빈 보상 상태에서 온도 증가, 새 주기의 빈 보상표를 검증한다.

이번 샘플에서는 학생·모둠 각각 한 대상을 사용하고 화면 체험용 칭찬·취소 버튼을 제공한다. 실제 저장·인증·학기 전환과 운영 검수는 앱 구현 단계에서 진행한다.
