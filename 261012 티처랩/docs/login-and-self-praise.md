# 학생 로그인과 직접 적립 요구사항

2026-10-14 갱신. 이 문서는 기존 PRD·도메인·화면·구현 계획 중 충돌하는 내용을 대체하는 최신 기준이다. 현재 결과물은 상호작용 샘플이며 실제 서비스의 인증·저장은 구현 전이다.

## 확정 요구와 적용 해석

| 항목 | 적용 기준 |
| --- | --- |
| 학생 식별 | 교사가 명단을 등록하면 학급 접속 화면에서 번호·이름 드롭다운 제공 |
| 학생 로그인 | 학생별 숫자 4자리 비밀번호. 이름만 선택해서는 기록을 볼 수 없음 |
| 교사 로그인 | 학생 PIN 및 칭찬 코드와 별개인 교사 비밀번호로 로그인 |
| 개인 칭찬판 | 네 영역을 대시보드에 동시에 표시. 각각 가로 30칸 막대, 위에 `획득 개수 / 30개` 표시 |
| 학생 직접 적립 | 로그인한 학생이 영역을 고르고 오늘의 칭찬 코드를 입력하면 +1 |
| 일일 제한 | 사용자 답변 ‘1일 최대 2번’을 학생별 네 영역 합산 2회로 적용 |
| 전체 일괄 칭찬 | 교사가 영역 선택 후 현재 학급 학생 모두에게 +1. 해당 영역 30개인 학생은 제외 |
| 취소 문구 | 모든 화면에서 ‘칭찬취소’로 통일 |
| 기존 유지 | 모둠 정리·다했어요 각 15개, 빨간 세로 온도계 0~100도·+5도, 보상 20칸은 최초 빈칸 |
| 제외 | 칭찬소식·비밀편지는 이번 제품 범위에서 제외 |

일괄 칭찬은 교사 직접 지급이므로 학생 직접 적립의 일일 2회에 포함하지 않는다. 칭찬취소는 교사만 수행하고, 취소해도 학생이 이미 사용한 당일 적립 횟수를 복구하지 않는다. 두 항목은 이번 요청을 구현하기 위한 적용 정책이며 사용자 확정 답변과 구별한다.

공통 코드와 하루 2회 제한은 무제한 적립을 막지만, 코드를 전달받은 학생이 실제로 칭찬을 받았는지까지 증명하지는 못한다. 이번 범위에서는 교사가 학생·영역·시각·직접 적립/일괄 지급 기록을 보고 취소할 수 있게 한다. 학생별 사전 승인 기능은 추가하지 않는다.

## 로그인과 명단

1. 교사는 학급 명단을 여러 줄로 등록하고 학생별 초기 4자리 PIN을 설정한다. 실제 서비스에서는 이름만 먼저 등록하고 초기 PIN을 발급하는 흐름도 지원 가능하다.
2. 학생의 내부 식별자는 변경되지 않는 studentId다. 동명이인은 출석 번호로 구별하며 이름 변경으로 칭찬 기록이 분리되지 않는다.
3. 학생은 자신의 현재 PIN을 확인한 뒤 PIN을 변경한다. 분실 시 담당 교사가 재설정하고 기존 세션을 만료시킨다.
4. 학생에게는 자기 개인 칭찬 기록과 허용된 학급 공통 자료만 반환한다. 다른 학생 ID를 요청에 넣어도 서버가 거부한다.
5. 명단은 해당 학급 접속 경로에서 번호·이름만 제공한다. PIN, 기록, 교사 비밀번호, 칭찬 코드를 명단 응답에 포함하지 않는다.
6. 4자리 PIN은 경우의 수가 적으므로 서버에서 계정별 실패 횟수·지연·임시 제한을 적용한다. 샘플은 5회 실패 시 1분 제한을 시연하며 운영 수치는 Phase 2에서 검증한다.
7. 교사 비밀번호는 4자리로 제한하지 않는다. 실제 운영에서는 초기 설정·변경·복구를 제공하고 샘플의 공개 비밀번호를 사용하지 않는다.

## 오늘의 칭찬 코드

- 챗봇이 매일 메시지로 보내는 방식 대신 앱 서버가 학급별로 자동 생성하고 교사 화면에서 확인하게 한다. 별도 예약 알림은 만들지 않는다.
- 학생 PIN과 구분하여 ‘오늘의 칭찬 코드’라고 부른다. 샘플은 숫자 4자리를 사용한다.
- 한국 시간 Asia/Seoul의 날짜를 사용한다. 서버가 학급·날짜별 안전한 난수를 생성하고 그날의 코드를 모든 교사 기기에 동일하게 제공한다. 전날 코드와 동일한 값은 재생성한다.
- 자정 작업과 첫 요청 시 생성 경로를 함께 두되 `(classroomId, localDate)` 유일 제약으로 한 개만 생성한다. 앱을 닫아 두거나 서버가 재시작되어도 같은 날 코드가 변경되지 않는다.
- 교사가 다시 조회할 수 있도록 코드는 서버 측 키로 암호화해서 보관한다. 학생 검증은 서버에서 수행하고 학생 화면/API 응답/로그/클라이언트 저장소에 정답 코드를 전달하지 않는다.
- 날짜가 바뀌면 이전 코드로 신규 적립할 수 없다. 서버 시간이 기준이며 기기 시간을 변경해도 횟수나 코드를 초기화할 수 없다.
- 서버는 학생·날짜별 직접 적립 사용량을 네 영역 합산으로 검사한다. 성공한 적립만 사용량을 늘린다. 오입력, 30개 상한 도달, 실패한 저장은 사용량을 늘리지 않는다.
- 재시도는 같은 idempotencyKey로 원래 결과를 돌려주며, 동시 요청은 DB 트랜잭션으로 일일 2회와 영역별 30개 상한을 함께 지킨다. 자정 이후 재시도도 이미 처리된 요청이면 새로 적립하지 않는다.
- 취소는 원본 삭제가 아닌 취소 기록으로 남긴다. 원본 날짜의 사용 횟수는 유지한다.

## 구현 Phase 추가 Step

기존 Phase 2와 Phase 3에 아래 항목을 합친다. 기존 ‘교사만 개인칭찬 생성’ 조건은 코드 검증을 통과한 본인 적립 예외를 포함하도록 변경한다. 기존 첫 화면 문구 검수는 로그인 후 대시보드에 적용한다.

**Step 2.6 학생 명단과 PIN 로그인** — 명단 드롭다운, 동명이인, 초기 PIN·변경·재설정, 담당 학급 확인을 구현한다.

**Step 2.7 교사 로그인과 세션 격리** — 교사 인증, 실패 제한, 공용 기기 로그아웃, 재설정 시 기존 세션 만료를 구현한다.

**Step 3.6 오늘의 코드와 학생 직접 적립** — 일일 코드 생성·날짜 변경, 코드 검증, 학생별 일일 2회와 영역별 30개를 원자적으로 적용한다.

**Step 3.7 전체 학생 일괄 칭찬** — 대상 학생 스냅샷, 동일 요청 중복 지급 방지, 완료 학생 제외, 지급·제외 결과 및 취소 기록을 구현한다.

**Step 3.8 막대형 대시보드** — 네 영역 30칸 가로 막대, 획득 개수, 적립 폼, 오늘 사용량, ‘칭찬취소’ 문구를 구현한다. 모바일에서는 30칸은 유지하고 숫자 눈금은 1·5·10·15·20·25·30으로 간소화한다.

### 추가 필수 Gate

| ID | 성공 조건 |
| --- | --- |
| G02-07 | 학생별 4자리 PIN·교사 비밀번호 검증, 오입력 제한, 동명이인 선택, PIN 재설정 후 이전 PIN·세션 무효화 |
| G02-08 | 학생 A의 세션으로 학생 B 조회·수정, 교사 전용 코드 조회·일괄 지급·취소 API를 호출하면 거부 |
| G03-09 | 동일 학생이 네 영역 합산 2회까지만 직접 적립. 3번째·동시 요청 거부, 다른 학생은 독립 제한 |
| G03-10 | 한국 자정 전후 코드 교체·구 코드 거부·사용량 초기화. 서버 재시작과 다중 기기에서도 오늘 코드 일치 |
| G03-11 | 취소는 보유 개수만 감소하고 당일 사용량은 유지. 취소 재요청 및 적립 재시도는 중복 처리하지 않음 |
| G03-12 | 일괄 지급은 대상 전원에게 최대 1개, 30개 학생 제외, 학생 사용량 불변, 재시도·동시 요청·실패 시 일관성 유지 |
| G03-13 | 첫 대시보드에 네 막대 각각 30칸·획득 숫자 표시, 원형 스탬프 없음, 하단 두 메뉴 유지, 320px 및 키보드 조작 검수 |

Phase 5 시상과 Phase 6 편지는 현재 범위에서 제외한다. Phase 7은 Phase 4 이후 진행한다. 제외는 PASSED나 테스트 skip 성공으로 처리하지 않고 범위 제외로 기록한다. 유지되는 Phase 7의 관련 산출물 역시 현재 범위에 한정한다.

## 샘플 검수와 실제 서비스의 차이

`docs/qa/check-classroom-demo.cjs`는 샘플에 포함된 동일한 로컬 모델을 추출해 12개 로직 검사를 실행한다. 인증·권한은 샘플 흐름을 위한 조건문일 뿐 서버 보안 검수가 아니다. 브라우저 표시, 여러 기기 공유, 데이터베이스 동시성, 실제 로그인·코드 암호화·자동 운영은 별도 구현·검수 대상이다. 샘플 통과를 Phase 2·3 통과로 기록하지 않는다.

실제 인증·권한 설계의 참고 기준: [OWASP 인증 가이드](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html), [OWASP 권한 가이드](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html). 로그인 시도 제한과 모든 요청에 대한 서버 권한 검증을 적용한다.
