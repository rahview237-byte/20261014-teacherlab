# 티처랩 · 우리반 칭찬 관리

학급 규칙과 개인·모둠 칭찬을 함께 관리하는 앱의 기획 문서 및 상호작용 샘플입니다.

**현재 단계: PRD·도메인·구현 계획 + 브라우저 샘플.** 서버, 데이터베이스, 실제 사용자 인증은 아직 구현하지 않았습니다. 실제 학생 정보나 비밀번호를 입력하지 마세요.

## 샘플 실행

저장소를 내려받은 뒤 루트의 [`index.html`](index.html)을 브라우저에서 여세요. 별도의 앱 설치나 빌드는 필요하지 않습니다. 아이콘·공통 스타일 등 일부 리소스는 인터넷 연결이 필요합니다.

필요하면 저장소 폴더에서 로컬 서버를 실행할 수 있습니다.

```sh
python -m http.server 8080 --bind 127.0.0.1
```

그런 다음 브라우저에서 `http://127.0.0.1:8080`으로 접속하세요. GitHub에 파일을 올리는 것과 웹사이트 배포는 별개이며, GitHub Pages는 아직 설정하지 않았습니다.

### 체험용 로그인

| 역할 | 이름 | 비밀번호 |
| --- | --- | --- |
| 학생 | 김하늘 | `1234` |
| 학생 | 이바다 | `2345` |
| 학생 | 박새봄 | `3456` |
| 교사 | 선생님 탭 선택 | `teacher2026!` |

모두 공개된 가상 체험 계정입니다. 학생으로 로그인하여 각 영역의 **칭찬 스티커 붙이기** 버튼을 누르면 바로 적립됩니다. 칭찬 코드 입력은 없습니다. 같은 페이지 안에서 역할을 전환하면 샘플 기록을 확인할 수 있고, 페이지를 새로 열면 초기화됩니다.

## 반영된 기능

- 학급 규칙: 자주적인 어린이, 긍정적인 어린이, 적극적인 어린이, 배려하는 어린이.
- 개인 칭찬판: 네 영역 각각 학기당 최대 30개, 가로 30칸 막대와 획득 개수 표시.
- 학생: 명단 드롭다운과 개인 4자리 PIN 로그인, PIN 변경, 버튼으로 본인 직접 적립.
- 하루 적립: 학생별 각 영역 최대 2회, 네 영역 합계 최대 8회. 취소해도 해당 영역의 당일 사용 횟수는 복구하지 않음.
- 교사: 별도 로그인, 명단 추가, 학생 PIN 재설정, 영역별 전체 학생 일괄 칭찬, 기록 확인·칭찬취소.
- 일괄 칭찬: 해당 영역에 학생당 +1, 30개인 학생 제외, 학생 직접 적립 횟수와 별도 처리.
- 모둠 칭찬: 정리와 다했어요 각각 최대 15개. 현재 샘플은 하나의 가상 모둠.
- 학급온도계: 빨간 세로형, 0~100도, 교사 칭찬당 +5도.
- 보상표: 5~100도까지 20개 빈 입력칸. 교사 화면에서 편집.
- 하단 메뉴: 우리 모둠 / 학급온도계. 칭찬소식·비밀편지는 현재 범위에서 제외.

## 중요한 구현 구분

샘플의 로그인과 권한 분기는 화면 흐름을 체험하기 위한 로컬 코드입니다. 실제 보안 수단이 아니며, 소스를 보는 사람은 체험 비밀번호와 로직을 확인할 수 있습니다.

칭찬 코드의 생성·표시·입력·검증 기능은 제거했습니다. 학생 로그인 PIN과 교사 로그인 비밀번호는 유지합니다. 적립 횟수는 한국 날짜 기준으로 영역마다 계산합니다.

실제 학생 데이터 저장, 서버 권한 검증, 안전한 자격증명 보관, 동시 요청 제한, 여러 기기 동기화는 다음 구현 단계입니다. 현재 샘플의 횟수 제한은 페이지를 새로 열면 초기화되며, 실제 서비스에서는 서버에 학생·날짜·영역별 사용량을 저장해야 합니다.

## 검수 실행

Node.js가 설치된 환경에서 저장소 루트에서 실행합니다. npm 패키지 설치는 필요 없습니다.

```sh
npm test
```

또는 다음 명령을 사용합니다.

```sh
node scripts/check-classroom-demo.cjs samples/classroom-login.fragment.html
node scripts/check-export.cjs
```

샘플의 실제 로컬 모델을 추출하여 12개 검사를 수행합니다. PIN·권한 분기, 코드 없는 직접 적립, 영역별 하루 2회·합계 8회, 취소, 날짜 경계, 일괄 칭찬, 30개 상한, 명단 검증, 비밀번호 재설정, 실패 제한, 모둠·온도 상한을 확인합니다. 이 자동 검사는 브라우저 화면이나 서버 보안·동시성을 검증하지 않으며, 통과 결과를 실제 앱 Phase 완료로 취급하지 않습니다.

## 파일 구성

```text
index.html                         # 브라우저에서 여는 최신 샘플
samples/
  classroom-login.fragment.html    # 최신 샘플 편집 원본
  classroom-welcome.fragment.html  # 이전 원형 스탬프 샘플 보관본
scripts/
  check-classroom-demo.cjs          # 샘플 로직 12개 검사
  check-export.cjs                  # 배포 파일 폼 처리 회귀 검사
docs/login-export-fix.md            # 브라우저 검수 결과
package.json                       # 의존성 없는 테스트 명령
```

`index.html`은 최신 fragment를 독립 실행 가능한 문서로 내보낸 결과입니다. 수정할 때는 원본과 내보낸 결과를 함께 갱신해야 합니다. 이전 샘플은 참고 이력이며 최신 요구의 구현 기준이 아닙니다.

### 배포 후 로그인 버튼이 반응하지 않는 경우

내보낸 iframe에는 `sandbox="allow-scripts allow-forms"`가 필요합니다. `allow-forms`가 빠지면 로그인뿐 아니라 스티커 적립·일괄 칭찬 등 폼의 제출 이벤트도 차단됩니다. 내보내기 도구로 다시 생성했을 때도 이 속성을 유지하고 `npm test`의 배포 파일 회귀 검사를 통과시켜야 합니다. `allow-same-origin`은 추가하지 않으며 CSP의 `form-action 'none'`도 유지합니다. 폼은 자바스크립트에서 처리하고 네트워크 전송을 하지 않습니다.

Netlify 주소가 앱 대신 **Team protection**으로 이동하면 앱 비밀번호 문제와는 별개입니다. 해당 사이트의 배포 접근 보호 설정을 확인해야 합니다. 실제 학생에게 공개하기 전 서버 인증·저장 구현이 필요하며, 이 샘플의 공개 체험 계정을 실제 계정으로 사용하면 안 됩니다.
